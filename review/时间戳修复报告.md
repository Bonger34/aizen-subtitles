## 二、时间戳修复

### 发现的缺陷
25 条条目的时间戳**超出视频实际长度**(P25 有 23 条,最多到 24m43s 而视频仅 24m14s;P20 有 2 条)。

### 定位方法
按项目既有铁律**顺序读帧**(禁用 `cap.set` 回跳),对每张配图在整片内逐帧比对,
取 MAD 最小的秒作为该图内容的真实时间(`locate_all.py`)。两次人眼复核确认:
视频 22m36s 画面 == 库存 `P25_23m00s.jpg`;视频 23m15s 画面 == 库存 `P25_24m15s.jpg`(「我们今天吃寿喜锅哦」)。

### 实测结论:P25 片尾是**整段错位**,不止越界那几条
偏移分布(内容时间 − 原时间戳):

| 偏移 | 条数 | 性质 |
|---|---|---|
| −50 ~ −72s | 41 | 真错位(24m00s–24m43s 整块) |
| −18 ~ −24s | 15 | 真错位 |
| −4 ~ −6s | 16 | 真错位(片尾职员表段系统性偏移) |
| −3 ~ +3s | 其余 | 测量噪声(±1s 量化),视为正常 |

### 修复方式
1. 按**内容真实秒**排序(当前顺序本身已被打乱,不能按原时间戳排);
2. 在【保持画面先后 + 同秒唯一】约束下,用 DP 求 Σ(新秒−实测秒)² 最小的分配
   (`retime_dp.py`,平方代价可抑制个别条目被推很远);
3. 帧文件同步重命名为 `{集}_{新时刻}.jpg`。

改动 **P25 78 条 + P20 2 条**,位移平均 1.5s、最大 4s。明细:`retime_P25.txt`、`retime_dp_P25.txt`、`retime_P20.txt`。

### 闭环复验(重新定位一遍)
| | 修复前 | 修复后 |
|---|---|---|
| \|偏移\| ≥ 8s 的条目 | 56 | **0** |
| \|偏移\| ≥ 4s 的条目 | 72 | **3** |
| 超出视频长度的条目 | 25 | **0** |

最终一致性:`frames_map` 6999 键 = 库 6999 条,缺键 0 / 缺帧 0 / 孤儿键 0,同秒重复 0,
`node verify_search.js` 408 命中 0 缺帧,覆盖率 100%。

   `我会买豆腐和葱的` ×2)。时间戳已各自修正,文本去重未做。
