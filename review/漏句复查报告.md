# 漏句复查报告(修好扫描脚本 bug 后)

## 结论

**确实还有漏句,而且量不小:补入 175 条台词,库从 7003 条增至 7169 条(+2.4%)。**

## 前一轮"没有漏句"的结论是错的 —— 原因是我自己脚本的 bug

密集扫描脚本 `scan_series_dense.py` 的取帧记账有 off-by-one:
```python
while n < f: grab(); n += 1        # 少算了 retrieve 本身消费的一帧
retrieve(); n += 1                  # 于是 n 比真实帧号多 1, 且每个采样点累积
```
后果:目标帧号比实际取到的帧**快 k 帧**(k = 已处理采样点数),一集内误差可累积到**上百秒**。
- 候选的**位置全错** → 与库的 ±5s 匹配失效 → 既漏判又误判;
- 我上一轮的抽查是按"记录位置"去视频找,自然找不到,于是误判为"候选是噪声"。

**修正后**:P06 候选从 241 条降到 107 条,并用「考虑下时间地点场合啊」验证位置正确(2m43.5s 画面即此句)。

## 复查流程

1. 用修好的脚本**重扫全 25 集**(区间 = 字幕带 ∪ 带下方,区间内 0.25s 密采,裁剪 y878–1075):
   约 **78,000 帧采样 / 约 19,000 次 OCR / 3,050 条候选**;
2. 与**全库**双向模糊匹配 + 按"只算台词"过滤(剔除片头片尾日文歌词、演职员表、帧计数器数字、
   图鉴/预告解说、跨集重复)→ **983 条疑似漏句台词**;
3. **逐条到视频复核**(候选秒 ±0.4s 三帧 OCR,候选文本需 ≥80% 复现)→ **750 条通过**;
4. 再策展(收紧图鉴/演职员表关键词、批内去重、排除片尾段)→ **175 条**;
5. 入库(抽该秒画面 + 追加条目),再手工剔除 6 条残留垃圾 → 净增 **166 条**。

## 漏收的成因(与证据一致)

漏掉的句子**几乎都夹在两条已收录条目之间**(如 5m33s 与 5m41s 之间的 5m36s/5m37s)。
说明当年的补扫只把**新检测到的区间**追加进库,而**已覆盖区间内新出现的句子没有被追加** ——
连续对白里,白像素检测一直处于 ON(没有回落到 OFF 的机会),整段变成一个区间,
后续补扫就把它当作"已覆盖"跳过了。

## 残余风险

- 本轮区间覆盖 = 字幕带 ∪ 带下方,密采 0.25s;时长 <0.25s 的字幕不会被采到(未观察到);
- 过滤时被判为"不像中文台词"(204 条)或"噪声/纯数字"(936 条)的样本中,可能仍有个别真句
  (通常是 OCR 读得太差);这部分未逐条人工核对;
- 片尾段(>=23m20s, P25 为 >=21m)未补录,按"只算台词"口径排除(该段是演职员表/歌词/图鉴解说)。
